# 维护、校验与发布

面向维护者，也提供用户可选的下载校验。当前正式版为 v1.3.0；开发命令见[开发指南](DEVELOPMENT.md)，本页规定提交和资产来源。

## 校验下载文件

在 [v1.3.0 Release](https://github.com/LeeAstra/autologin-sias/releases/tag/v1.3.0)下载需要的 EXE 和 `SHA256SUMS.txt`。在 Windows 文件资源管理器打开下载目录，地址栏输入 `powershell` 并回车，再执行只读命令：

```powershell
Get-FileHash -LiteralPath .\AutoLogin_SIAS_Installer.exe -Algorithm SHA256
Get-Content -LiteralPath .\SHA256SUMS.txt
```

找到校验文件中同名一行，与输出 Hash 比较；大小写不同无影响，字符必须一致。后台 EXE 同理换成对应文件名。文件名或位置不同则修改 `-LiteralPath`，不要把示例输出粘贴为命令。不一致先停止使用，重新检查下载来源。

正式安装器 SHA256：

```text
90477aa3c2e82081f95456bc4ae225d12ca8b7c3eb1c762da7f9b2d59c798d36
```

正式后台 SHA256：

```text
7ff4bce7932efe5c270de9e38df25d4c665824d175ef200af5ab52463f9d71b2
```

SHA256 用于核对文件完整性和一致性，不是代码签名，也不代表任何安全软件必然放行。v1.3.0 安装包未签名。

## 贡献流程

1. 从最新 `main` 建立一条短期分支，例如 `codex/简短主题`；一次 PR 聚焦一个可说明的改动。
2. 按影响运行[对应检查](DEVELOPMENT.md#测试)，更新相关指南和变更说明。文档改动只做链接、事实和阅读验证，不自行重打历史包；仓库现有 CI 仍会执行完整检查。
3. 提交 PR，按模板说明问题、改动、验证及影响。任务触发、电源条件或协议变化必须明示，不能夹带在整理中。
4. 等待必需检查和讨论解决后合并，删除已合并远端功能分支；提交、PR 和标签保留。

当前 `main` 规则要求 PR 和 `test-and-build` 通过、分支保持最新、讨论解决，禁止强推和删除。设置合并后自动删除分支；不绕过保护。个人项目不要求强制审批数量，不等于无需审阅。

不要提交 EXE、构建目录、真实配置、凭据、捕获资料或用户结果。实验源码放在 `tools/experiments/`，公开复现使用合成夹具。

## 发布新版本

1. 确定范围并更新唯一版本文件 `src/sias_autologin/version.py`、`CHANGELOG.md` 和指南。兼容功能通常递增次版本，修复递增补丁；缺少必要验收时使用 `-rc.N`。
2. 从拟发布的干净提交构建两个 EXE，并运行完整源码、冻结包和隔离安装验证。核对 `BUILD-INFO.json`、CI 验证提交和打包来源。
3. 根据变更补做真实网络、任务事件、升级/恢复验收；预先说明会改变正式任务、断网或覆盖配置的具体影响。模拟结果不能替代实机证据；可参考[历史验收清单](history/v1.3.0-acceptance-checklist.md)并按新版本调整。
4. 通过后按仓库保护合并，核对合并源码树与已验证来源。标签指向实际验证、打包的提交，不用未验证提交补标签。
5. 先创建草稿，上传**同一组已验证的四个附件**，核对服务器摘要，再公开 Release。预发布不替换稳定 Latest；CI 产物不会自动发布。
6. 核对正式标签、版本、附件摘要和下载链接，更新当前文档入口，保留限制与验收结论。

不移动历史标签、不覆盖已发布二进制。后续文档补充可通过 PR 及 Release 文字说明发布，不需要重新打包旧版本。发现影响认证、安装、升级或恢复的代码问题，单独报告并走修复流程，不能改文案掩盖。
