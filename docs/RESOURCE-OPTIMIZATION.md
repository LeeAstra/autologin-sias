# WLAN 资源优化候选 rc.5

仅 Windows 平台层替换循环 netsh；认证核心没有 Windows 依赖。夜间5秒、持续30秒、失败至少15秒后重试、休眠等待和状态变化日志保持。最新认证状态未知不提交；提交前重新确认 UESTC，并在检测完成后重查夜间窗口。已开始请求允许完成恢复确认。任务、电源和安装目录规则不变。

API函数绑定来自System32，连接状态每次重新查询。释放枚举/查询内存并关闭会话；服务不可用、访问拒绝、数据异常和连接过渡都返回未知。不同Wi-Fi或明确断开返回离网；多网卡任一明确连接UESTC为目标网络。

自动化覆盖 UESTC、其他Wi-Fi、无接口、断开、多网卡、过渡、服务不可用、权限拒绝、短响应、异常和重复资源释放。此前失败消息、最新未知状态、窗口边界、验收日志归属和安装互斥回归继续执行。生产冻结EXE测试实际认证与安装回滚；另建测试专用冻结包替换Wi-Fi观察，验证维护策略。该测试包不进入安装载荷或候选下载。

## 实机验收（尚需人工完成）

构建候选与运行CI不等于通过整夜校园网验收。不要为测试修改计划任务或电源条件。请在方便切换网络时执行：

1. 先保存当前日志和安装版本。按原位升级选择已有目录和相同模式，不改时间窗口。
2. UESTC下观察新轮次；其他Wi-Fi和断开时应记录 left_target_wifi 并退出，未知状态不得提交凭据。
3. 两块无线网卡时，只有至少一块明确连接UESTC才允许运行。存在未确认接口且无目标连接时应等待。
4. 睡眠恢复后检查新鲜网络观察；若仍处于夜间窗口可继续，超过结束时间不得新提交。不要为实验开启唤醒或防休眠。
5. WLAN服务不可用用自动化替身验证，无需停掉办公网络服务。Windows隐私/位置权限不足应返回未知；请在设置中手动确认访问权限，程序不会自行改变权限。
6. 用原只读 `scripts/windows/Get-AcceptanceStatus.ps1` 收集本轮证据。核对提交时间在窗口内，明确登出后有 confirmed=true；没有发生登出应写未观察到，不能算重登通过。

固定回复：

```text
候选版本：1.3.0-rc.5
模式：night / continuous
UESTC：通过 / 未通过 / 未测
其他Wi-Fi与断开：通过 / 未通过 / 未测
多网卡：通过 / 未通过 / 无设备
睡眠恢复：通过 / 未通过 / 未测
任务账户WLAN权限：通过 / 未通过 / 未确认
实际登出时间：时间 / 未观察到
确认恢复时间：时间 / 未确认
窗口外提交认证：没有 / 有 / 未确认
验收JSON：粘贴完整JSON
```

读取API的权限必须在实际任务账户中确认，交互式Python成功不能替代S4U任务验收。近期Windows的Wi-Fi查询可能受位置访问权限约束，见[Microsoft官方说明](https://learn.microsoft.com/en-us/windows/win32/api/wlanapi/nf-wlanapi-wlanqueryinterface)。
