适用于 v1.3.1。先判断任务有没有运行，再判断门户认证有没有恢复；无需先学习 Python。安装和日常操作见[使用指南](USAGE.md)。

## 火绒或其他行为防护提示

安装器会调用系统 Windows PowerShell 执行随包的 `Install-AutoLoginTask.ps1`，预检、备份和注册本应用任务；安装事务也用 PowerShell 查询、停止、启动和失败恢复任务。日常维护任务执行后台 EXE，循环中的 Wi-Fi 查询使用 WLAN API。

`-ExecutionPolicy Bypass` 只作用于该次 PowerShell 进程的脚本执行策略，不会关闭安全软件或修改系统持久执行策略。不要通过关闭防护、整个目录加白或直接删除这个参数解决告警。

2026-10-08 用户报告火绒告警结果为“已允许”；之后任务配置、发布文件摘要和实际运行已核验。原始告警详情未独立取得，不能据此保证所有版本和策略均兼容。[验收记录](releases/v1.3.1-acceptance.md#安装行为防护复核2026-10-08)。

1. 在防护日志查看告警时间、安装器/PowerShell/脚本路径、命令和处理结果，并检查文件是否来自正式 Release。
2. 用[校验步骤](MAINTENANCE.md#校验下载文件)核对下载摘要；“已允许”之后按下面方法检查任务和运行结果。
3. 如果被拦截，保留告警及安装错误，先核对恢复状态再反馈，不反复重试或清空任务。截图或命令含个人路径时可脱敏。

原生任务接口替换是后续评估，本版保持现有安装流程。

## 确认任务和本轮运行

1. 按 `Win + R`，输入 `taskschd.msc`。在“任务计划程序库”找到 `AutoLogin_SIAS`；看不到时先确认安装是否完成和账户是否一致，权限不足可用当前账户管理员权限查看。
2. 打开“属性 → 操作”，核对 EXE 是否存在及参数；“触发器”中夜间模式应有每日 02:55。安装器注册成功只证明任务配置已写入。
3. 查看状态和上次结果：持续模式在 UESTC 下通常“正在运行”；夜间窗口外“就绪”、`0x0`、日志 `outside_night_window` 为正常退出，不代表本次重登。
4. 在操作指定的安装目录，用记事本打开 `auto_login_headless.log`。每个 `start` 有独立 `run_id`，同一编号的 `state`、`login_result`、`end` 才属于同一轮。

`state=authenticated` 证明当时门户认为在线；`auth_required` 表示明确需要认证；`unknown` 表示证据不足。`login_result` 中 `submitted=true` 是实际提交，`confirmed=true` 且 `exit_code=0` 是确认恢复。长期在线只记录状态变化，没有每五秒一条日志是正常的。

| 状态或结果 | 判断 |
|---|---|
| `Running` / “正在运行”，`267009`（`0x41301`） | 运行中，不能按失败处理 |
| `Ready` / “就绪”，`0` | 检查退出原因；可能是窗口外或离开 UESTC，并非必然完成登录 |
| `2147946720`（`0x800710E0`） | 启动请求被拒绝，需要结合调度日志；本轮实机曾因已有实例运行而拒绝重复触发，不能一律忽略 |
| `UNKNOWN_VERSION`、`unconfirmed` | 没有匹配本轮的完整证据，不能推断成功 |
| 持续模式 `next_run=null` | 没有固定下次定时运行，正常 |

需要查看拒绝原因时，打开事件查看器“应用程序和服务日志 → Microsoft → Windows → TaskScheduler → Operational”，按相近时间和任务名称查找。记录中事件 322 可表明已有实例拒绝重复启动；不要仅凭错误码归因。未启用历史记录时也可能没有该事件。

### 可选：只读采集

在**当前账户的管理员 Windows PowerShell**中粘贴以下命令，只读取状态，不启动任务或认证。无需下载源码：

```powershell
$task = Get-ScheduledTask -TaskName 'AutoLogin_SIAS' -TaskPath '\'
$info = Get-ScheduledTaskInfo -InputObject $task
[ordered]@{
    executable = @($task.Actions | ForEach-Object { $_.Execute })
    arguments = @($task.Actions | ForEach-Object { $_.Arguments })
    enabled = [bool]$task.Settings.Enabled
    state = [string]$task.State
    last_result = [long]$info.LastTaskResult
    missed_runs = [int]$info.NumberOfMissedRuns
    last_run = $info.LastRunTime.ToString('yyyy-MM-dd HH:mm:ss')
    next_run = if ($null -ne $info.NextRunTime) {
        $info.NextRunTime.ToString('yyyy-MM-dd HH:mm:ss')
    } else { $null }
} | ConvertTo-Json -Depth 4
```

已有源码的维护者还可在仓库根目录执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Get-AcceptanceStatus.ps1`，采集当前轮次结构化证据。它只匹配最近任务运行；早晨新触发可能使结果不再包含凌晨重登，需要另保留完整夜间记录。运行失败时返回错误原文，不把之前保存的 JSON 当作新结果。

## 程序运行但未恢复网络

1. 先确认电脑在维护窗口内且保持唤醒，Wi-Fi 确实为 UESTC。持续模式才会全天检测。
2. 查看本轮状态和认证结果。未知状态不登录是保护行为；没有自然登出时也不应为了测试反复提交密码。
3. 打开浏览器访问 `http://2.2.2.3`，检查门户能否访问；再访问常用网页检查外网。门户恢复与外网恢复分别判断。
4. 如果使用 VPN 或代理，检查发往 `2.2.2.3` 的请求是否通过校园网直连；全局隧道和系统代理都可能影响后台请求。按所用软件配置该地址的直连规则，不能只修改浏览器代理。

若要通过暂时断开 VPN 做对比，会中断依赖 VPN 的连接，先保存工作；不要为排查关闭安全防护。若当前确需手动登录可使用校园门户，但这样会影响自动重登实验，反馈中说明操作时间。

后台退出码参考：`2` 缺少凭据，`4` 异常 HTTP 状态，`5` 明确拒绝，`6/7` HTTP 或网络异常，`8` 无法确认，`9` 未预期错误。维护登录的错误记在 `login_result`，循环可能继续重试；任务整体退出码与一次认证的退出码不一定相同。

## Wi-Fi 无法识别

1. 在 Windows 网络界面核对 Wi-Fi 名称（SSID）是否准确为 `UESTC`，确认无线连接而非仅有有线或其他 Wi-Fi。
2. 查看 `network_unverified`、`unknown` 或 `left_target_wifi`。未知表示无法确认，明确离开目标网络才会退出。
3. 在“服务”中只读查看 WLAN AutoConfig 是否运行，并检查当前 Windows 的 Wi-Fi/位置访问权限。不要为了测试停掉服务或改电源条件。
4. 多无线网卡只需至少一块明确连接 UESTC；没有目标连接而仍有未核实接口时可能等待。此场景有模拟覆盖，尚无本轮多网卡实机验证。

交互账户能识别 Wi-Fi 不证明计划任务账户也能识别，反馈时提供任务模式、状态变化和权限提示。

## 凭据验证失败或配置冲突

安装会强制验证本次保存的配置；在线状态不能证明新密码正确。`5` 表示明确拒绝，`8` 表示结果无法确认，后者不要直接归因为密码错误。

1. 在同一网络下检查校园门户能否访问，确认输入的是校园网凭据而非 Wi-Fi 或 Windows 密码。
2. 要修改凭据时按[使用指南](USAGE.md#升级切换模式或更换凭据)重新运行完整安装器，在旧配置提示处输入 `n`。不要在真实门户上连续尝试错误密码。
3. 如果过去设置过 `WLAN_USER` 或 `WLAN_PWD` 环境变量，在 Windows“编辑账户的环境变量”中私下检查它们与配置是否冲突。普通后台仍保留非空环境变量优先语义；安装验证忽略这些覆盖。

需要调整环境变量时先记录原设置，它可能影响其他旧部署；变更后在合适时机重新启动维护并核验实际使用结果。不要把变量值或真实 `.env` 发到公开 Issue。

## 安装及恢复失败

先保留窗口“部署未完成”之后的原文、失败阶段和备份路径，不先删任务或配置。

| 提示 | 下一步 |
|---|---|
| 旧任务不支持 / 同账户权限不符 | 核对任务账户、操作和触发器；预检失败应在停止任务和替换文件前退出，不删除任务绕过 |
| EFS 加密目录 | 重新选择未启用 EFS 的本地目录；不要为此解密整个办公目录 |
| `WLAN event log is disabled` | 在事件查看器只读确认 WLAN-AutoConfig/Operational 状态，反馈原文；如需启用须明确其影响后操作 |
| 原文件和任务设置已恢复 | 检查原目录和任务状态，确认恢复后再针对失败原因重试 |
| 自动恢复未完成 | 保留当前文件与备份，按下面模板反馈；不要盲目导入另一账户的 XML |
| 文件被占用或多个安装器竞争 | 关闭其他安装窗口，核对[已确认目录的残留进程](USAGE.md#暂停恢复和卸载)，不要按名称批量杀进程 |

文件备份位于 `%LOCALAPPDATA%\AutoLogin_SIAS_Backups`，可能包含 `task-before.xml`、`target-*` 和旧目录文件。修复恢复时需要将这些与原任务、原目录逐一对应；本指南不提供未经个案核对的覆盖命令。新装失败可能留下空目录或诊断日志，不能只凭目录存在认为安装成功。

正常安装目录不能写日志时，程序可能写到 `%TEMP%\auto_login_headless_进程编号.log`；仍失败则可能没有文件日志。默认目录找不到日志时在反馈中说明，不冒用其他目录旧日志。
