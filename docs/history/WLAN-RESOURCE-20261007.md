# WLAN 资源优化候选 rc.6

> 历史归档：下文保留记录当时的版本、流程和待办，不代表当前状态。v1.3.0 已正式发布；当前操作见[使用指南](../USAGE.md)，完成结论见[最终验收](../releases/v1.3.0-acceptance.md)。

仅 Windows 平台层替换循环 netsh；认证核心没有 Windows 依赖。夜间5秒、持续30秒、失败至少15秒后重试、休眠等待和状态变化日志保持。最新认证状态未知不提交；提交前重新确认 UESTC，并在检测完成后重查夜间窗口。已开始请求允许完成恢复确认。任务、电源和安装目录规则不变。

API函数绑定来自System32，连接状态每次重新查询。释放枚举/查询内存并关闭会话；服务不可用、访问拒绝、数据异常和连接过渡都返回未知。不同Wi-Fi或明确断开返回离网；多网卡任一明确连接UESTC为目标网络。

自动化覆盖 UESTC、其他Wi-Fi、无接口、断开、多网卡、过渡、服务不可用、权限拒绝、短响应、异常和重复资源释放。此前失败消息、最新未知状态、窗口边界、验收日志归属和安装互斥回归继续执行。生产冻结EXE测试实际认证与安装回滚；另建测试专用冻结包替换Wi-Fi观察，验证维护策略。该测试包不进入安装载荷或候选下载。

## 实机验收（尚需人工完成）

构建候选与运行CI不等于通过整夜校园网验收。不要为测试修改计划任务或电源条件。请在方便切换网络时执行：

1. 先保存当前日志和安装版本。按原位升级选择已有目录和相同模式，不改时间窗口。
2. UESTC下观察新轮次；其他Wi-Fi和断开时应记录 left_target_wifi 并退出，未知状态不得提交凭据。
3. 两块无线网卡时，只有至少一块明确连接UESTC才允许运行。存在未确认接口且无目标连接时应等待。
4. 睡眠恢复后检查新鲜网络观察；若仍处于夜间窗口可继续，超过结束时间不得新提交。不要为实验开启唤醒或防休眠。
5. WLAN服务不可用用自动化替身验证，无需停掉办公网络服务。Windows隐私/位置权限不足应返回未知；请在设置中手动确认访问权限，程序不会自行改变权限。
6. 用原只读 `scripts/windows/Get-AcceptanceStatus.ps1` 收集本轮证据。核对提交时间在窗口内，明确登出后有 confirmed=true；没有发生登出应写未观察到，不能算重登通过。

固定回复：

```text
候选版本：1.3.0-rc.6
模式：night / continuous
UESTC：通过 / 未通过 / 未测
其他Wi-Fi与断开：通过 / 未通过 / 未测
多网卡：通过 / 未通过 / 无设备
睡眠恢复：通过 / 未通过 / 未测
任务账户WLAN权限：通过 / 未通过 / 未确认
实际登出时间：时间 / 未观察到
确认恢复时间：时间 / 未确认
窗口外提交认证：没有 / 有 / 未确认
验收JSON：粘贴完整JSON
```

读取API的权限必须在实际任务账户中确认，交互式Python成功不能替代S4U任务验收。近期Windows的Wi-Fi查询可能受位置访问权限约束，见[Microsoft官方说明](https://learn.microsoft.com/en-us/windows/win32/api/wlanapi/nf-wlanapi-wlanqueryinterface)。

## 开销测量

工具和指标定义见[测量工具](../../tools/experiments/resource-benchmark/README.md)。2026-10-07，本机Windows 11 x64 / Python 3.13.5，真实UESTC连接，源代码维护循环＋生产认证核心＋loopback HTTP服务。旧检测来自8809b05。CPU为父进程与netsh子进程累计时间之和；包含测量程序和模拟服务开销，不能当作后台EXE独占资源。

消除采样器偏差后的5分钟纯在线对照（四组同时运行，共享背景负载；各模式保持相同间隔）：

| 指标 | 夜间旧→新（5秒） | 持续旧→新（30秒） |
|---|---:|---:|
| 累计CPU秒 | 6.141 → 2.313（下降约62%） | 0.891 → 0.438（下降约51%） |
| netsh启动次数 | 59 → 0 | 10 → 0 |
| 父进程峰值RSS MiB | 43.7 → 51.9 | 37.6 → 39.0 |
| 子进程峰值RSS MiB | 17.1 → 0 | 17.1 → 0 |
| HTTP状态查询次数 | 59 → 59 | 10 → 10 |
| HTTP凭据认证次数 | 0 → 0 | 0 → 0 |
| 在线状态日志次数 | 1 → 1 | 1 → 1 |

父进程峰值RSS在夜间样本中升高约8MiB，不能宣称父进程更省内存，也不能相加不同时间的父/子峰值当作总峰值。独立3批、合计3000次WLAN查询，句柄175/177/175，RSS约21.5/21.6/21.6MiB，未见持续增长；这是当前样本观察，不是整夜无泄漏证明。

另做10分钟纯在线对照：夜间netsh117→0、持续20→0，认证请求均0，在线日志均1。夜间状态查询117→118，间隔仍为5秒，差异来自检测耗时和测量截止边界；该组旧版使用采样器，CPU不纳入上表。

顺序运行的模拟登出（夜间60秒、持续90秒）：

| 指标 | 夜间旧→新 | 持续旧→新 |
|---|---:|---:|
| 登出到确认恢复秒 | 1.505 → 1.009 | 15.868 → 15.597 |
| HTTP凭据认证次数 | 1 → 1 | 1 → 1 |
| HTTP状态查询次数 | 14 → 14 | 5 → 5 |
| 总HTTP请求次数 | 17 → 17 | 8 → 8 |
| netsh启动次数 | 15 → 0 | 6 → 0 |

当前样本中恢复未变慢、凭据认证没有增加。持续模式的约15秒来自模拟登出与30秒轮询的相位，不能理解为固定恢复时间；夜间也不能据此承诺1秒恢复。真实恢复还包括最多一轮轮询等待、门户响应和失败重试。

真实rc.5冻结EXE也确认UESTC并完成在线loopback查询，零认证提交。78项单元回归、任务XML与验收证据、冻结认证和安装互斥检查通过；CI覆盖Linux核心与Windows构建/冻结检查。其他Wi-Fi、多网卡、服务失败和睡眠过渡已用API替身覆盖，实际切网、睡眠、S4U账户与整夜强制登出仍按上方清单验收。

完整脱敏汇总：[测量数据](../benchmarks/wlan-20261007.json)。暂不降低Wi-Fi查询频率，不引入网络状态缓存或事件监听。

## rc.6审查修复

上方资源实测和真实冻结WLAN检查记录对应rc.5，不冒充rc.6重新测量。rc.6收紧文字成功格式，未提交认证不进入冷却，保持正常检测频率；真正提交仍至少等待15秒。维护回调统一LoginResult，删除整数兼容分支。使用最新rc.6进行A～E实机验收，旧结果可作历史证据。
