# v1.3.0 安装、升级与恢复

本页说明拟发布的 v1.3.0。发布状态以 GitHub Release 为准；当前包仍待实机验收，不能把版本号当作已发布证明。

## 安装

Windows x64，连接 UESTC，用同一 Windows 管理员账户运行 `AutoLogin_SIAS_Installer.exe` 并允许 UAC。默认目录 `%LOCALAPPDATA%\AutoLogin_SIAS`，可以输入其他未启用 EFS 加密的绝对本地目录。不要使用其他管理员账户提权。

模式 1 为 UESTC 持续维护，每30秒检测；明确离开 UESTC 后退出。模式 2 为夜间维护，默认每天02:55～03:15，每5秒检测。默认选择模式2。开始时间包含在窗口内，结束时间不包含；提交前重新核对 Wi-Fi 和时间窗口，已开始的请求允许完成。不改变原有电源条件，不自动唤醒电脑。

输入校园账号密码，确认部署。安装时即使已在线也提交配置文件中的凭据验证，环境变量不能替代这些凭据；明确拒绝或结果不明不报告验证成功。后台普通运行仍保留环境变量优先的兼容行为，环境变量和配置不一致时应由用户统一，不能假设安装验证证明环境变量正确。

## 升级与迁移

完整安装器升级同时更新 EXE、任务脚本和任务配置。只有替换后台 EXE 不会切换任务模式。使用当前任务路径原位升级，或选择新目录迁移。读取旧安装状态前持有跨进程安装锁；先以同一任务脚本只读生成预览，检查旧任务是否可升级，检查失败时不停止任务、不替换文件。

旧任务必须属于同一账户，只有一个 Exec 操作和一个 Principal，使用 S4U 或 InteractiveToken；参数为空或已知维护模式。多 WLAN 触发器、非本应用事件和不支持的触发器会拒绝自动迁移。不要为升级删除不了解的旧任务或绕过错误。

原文件及完整任务 XML 先备份到 `%LOCALAPPDATA%\AutoLogin_SIAS_Backups`。注册和启动失败时恢复原文件、完整 XML、启用状态及原运行状态；恢复失败会明确提示备份路径。独立旧单次安装调用保留既有兼容语义，现代安装向导使用完整事务。

**迁移后保留旧目录中的三个程序/配置文件及其他文件。** `Start-ScheduledTask` 成功只表示请求被接受，不能证明维护已运行；夜间模式在白天正常退出也不能按失败处理。因此本版不因启动请求成功自动清理旧文件，会明确提示。确认新任务实际执行的 EXE 路径、新版本运行日志及网络恢复后，旧文件再由用户处理。不要手动启动旧目录中的程序。

## 配置向导及恢复

源码使用 `PYTHONPATH=src` 后运行 `python -m sias_autologin --setup`，或使用原有控制台 Setup 构建。发布的 Headless EXE 无控制台，普通用户通过完整安装器输入配置，不在无窗口 EXE 中运行交互向导。

`--setup` 测试的是本次保存的 `.env`，不会借用旧环境变量；即使原来已在线也验证凭据。失败时配置仍已保存，提示包含失败退出码，不报告成功；可以重新运行向导修正。安装器的失败恢复与此独立向导行为不同。

安装失败先保留错误原文、备份路径和当前任务状态，不手动删除文件或重新创建任务。自动恢复成功后，检查失败原因再重试；自动恢复未完成时，用备份中的 `task-before.xml` 和 `target-*` 文件核对恢复，不把未经核对的 XML 导入其他账户。

## 校验与限制

对下载的两个 EXE 运行 `Get-FileHash -Algorithm SHA256`，与同包的 `SHA256SUMS.txt` 比较。`BUILD-INFO.json` 记录拟发布提交、构建版本及这两个文件的 SHA256；只发布验证过的同一组二进制。

只适配已验证的 SIAS 协议及 UESTC SSID；门户认证不等于外网一定可用。未知认证或 Wi-Fi 状态不提交维护认证。实际提交失败后重试至少15秒，未提交则保持原检测周期。WLAN 服务、权限或定位设置异常可能导致无法核实网络；此时等待而不是盲目登录。计划任务账户、睡眠恢复和夜间自然登出须实机验证。安装包未做代码签名；本版不新增签名、其他平台安装器或缓存/事件监听。
