# 循环认证状态监测

独立测试 EXE，默认每秒检测一次门户认证状态。正常在线不提交登录；需要认证时交叉检查跳转，再调用打包时的原登录流程。默认至下一次本地 08:00 结束，也可持续运行。不会注册、更改、停用任何计划任务，也不会替换已安装程序。

## 每晚使用

1. 连接 UESTC。新版源码通过 Windows WLAN API 确认连接；旧监测 EXE 使用其构建时的检测实现，修改源码不会更新旧 EXE。保持接电，不关机、不合盖；运行期间会阻止自动睡眠。
2. 停止其他夜间监测窗口。本程序与旧夜间监测共用互斥锁，避免同时重登。
3. 为隔离实验，建议你手动在任务计划程序中禁用 `AutoLogin_SIAS`，测试结束后启用。实验期间固定程序版本，避免同时更换正式程序。本程序不会自动禁用它。
4. 打开本文件夹，在地址栏输入 `powershell` 并按回车，运行：

   ```powershell
   .\AutoLogin_SIAS_Monitor.exe
   ```

看到 `authenticated` 后可以锁屏离开。终端只显示状态变化及重登结果，但每次检测都写入文件。结束后电源行为恢复。Ctrl+C 可提前结束，直接关闭窗口/断电可能留下未结束标记。

持续运行直到 Ctrl+C：

```powershell
.\AutoLogin_SIAS_Monitor.exe --continuous
```

修改参数示例：

```powershell
.\AutoLogin_SIAS_Monitor.exe --interval 0.5 --until 07:00
.\AutoLogin_SIAS_Monitor.exe --env 'D:\AutoLogin_SIAS\.env'
.\AutoLogin_SIAS_Monitor.exe --observe-only
```

默认读取本目录 `.env`，否则读取 `%LOCALAPPDATA%\AutoLogin_SIAS\.env`。不复制、不修改配置。无需安装 Python。

建议先使用 1 秒间隔，0.5 秒仅供可控的短期对比，尚未验证长期高频查询会不会影响门户限流或会话有效期。检测按开始时间调度，慢请求时不会补发一串请求，至少间隔 0.1 秒。未知状态或网络不匹配会放慢检测。Wi-Fi 每约 5 秒复查，提交登录前再次确认目标 SSID，无法确认时不提交密码。

认证失败后的重试间隔默认 5、10、20、40、60 秒递增（每次完成后计时），恢复认证后重置。`--retry` 改初始间隔，最少 2 秒。资料查询超时 3 秒、根地址请求超时 8 秒；原认证各请求沿用原程序 12 秒超时。这些是各次网络操作超时，不是固定的整段耗时上限。恢复认证后额外做一次最长约 3 秒外网探测，结果不用于触发重复认证。

## 记录与汇总

记录全在本文件夹 `results` 中：

- `run-*.json`：每次运行摘要、失效事件、最后在线/首次发现失效/恢复时间、重试与详细记录文件名。
- `samples-日期-运行编号.jsonl`：每次状态检测及状态变化，跨午夜自动换文件。
- `proof-*.json`：启动、状态改变、异常或认证失效时的根地址证据（脱敏 HTTP 跳转及页面）。
- `login-*.json`：每次真正认证的详细请求/响应及耗时。
- `internet-*.json`：重登恢复门户认证后的独立外网确认。

每次运行摘要包括整晚事件，因此“今晚”可直接按运行分组；每日采样文件按本地自然日划分。不要只发摘要中的次数，分析时还需详细证据。

```powershell
.\AutoLogin_SIAS_Monitor.exe --summary
```

`observed_loss=true` 才是本次先观察到已认证、之后失效的事件。启动就未认证不计一次已观察到的登出。连续失效算一个事件，恢复后再失效才算下一次。切换网络、无法确认 Wi-Fi、睡眠/长时间采样中断会标记 `censored`，这些事件的恢复耗时无法完整测量。失效发生在最后已认证和首次检测需认证之间；不能仅凭状态变化断定服务器强制登出。

`recovered_at` 表示门户认证恢复，不等于外网一定可用；`internet_after` 另行确认。外网超时只标未知，不作为失效证据。查询失败/证据冲突不记为认证失效，也不会盲目提交登录。

每秒采样会产生较多日志。如需私下分析，先检查并脱敏所需结果；公开反馈使用[固定模板](../../../docs/TROUBLESHOOTING.md#反馈问题)，不要直接上传整批真实结果或 `.env`。账号密码、加密密码、auth_tag、Cookie 等会遮蔽，仍建议分享前检查记录。频繁状态查询是否延长会话尚未验证；必要时与低频观察做对照。

## 源码与构建

仓库只发布源码；先在本目录构建 EXE，再按上面的命令运行。已构建 EXE 内置构建时的正式登录模块，修改源码不会改变它；重新构建才会纳入新版的先检测再登录流程。连续实验请固定同一个构建和参数，保留本地 BUILD-INFO.json。

源码直接运行：`python .\monitor.py`。

源码检查：`python .\test_monitor.py`。构建：`powershell -ExecutionPolicy Bypass -File .\Build.ps1 -Python '实际路径\python.exe'`，需要 Python 和 PyInstaller。
